# data — 입력 데이터

**결론**: 파일 이름과 위치를 그대로 두고, **엑셀 등으로 열었다가 다시 저장하지 않는다.**
다시 저장하면 바이트(인코딩·줄바꿈·숫자 표기)가 바뀌어 원자료와의 동일성 확인이 어려워진다. `bash check_env.sh` 8절이 아래 sha256으로 확인한다. 원자료는 유지하며, 수정된 전처리는 `python run_all.py` 실행 중 메모리에서 적용한다.

## 파일

| 항목 | 값 |
|---|---|
| 파일 | `okm_augumented_2021.csv` (파일 이름의 `augumented` 철자는 원본 그대로) |
| 모양 | **6,168행 × 18열** — 257일 × 24시간 |
| 기간 | 2021-01-01 00시 ~ 2021-09-14 23시, 1시간 간격 |
| 크기 | 437,447 B |
| 형식 | UTF-8 (BOM 있음), 줄바꿈 CRLF, 쉼표 구분 |
| sha256 | `8f7af2e49366c93e1d6f5fdef4b5e350066c1792ac463c2c2886e370f4674830` |

코드는 `data/okm_augumented_2021.csv` 를 **상대경로**로 읽는다. 그래서 명령은 항상 패키지 폴더에서 실행한다.
직접 확인하려면:

```bash
python -c "import hashlib;print(hashlib.sha256(open('data/okm_augumented_2021.csv','rb').read()).hexdigest())"
```

## 데이터의 특징 (분석 결과에 영향을 준 것)

- **증강 복제일**: 전력 프로파일이 완전히 같은 날들이 **45개 그룹**을 이루고, 그중 잉여(복제) 일수가 **115일**이다.
  기온은 날마다 달라 행 단위 중복 검사로는 잡히지 않는다. 그래서 복제일을 남긴 조건(D1)과 뺀 조건(D2)으로 실험을 모두 돌렸다
  (`outputs/tables/ch1_profile_dup.csv`, `ch3_data_conditions.csv`).
- 전력이 0 인 계측정지 구간과 ERP 생산량이 빠진 가동일이 있다. 1.2·1.3 단계가 진단·정비하고 그 기록을 `ch1_quality.csv`·`ch1_repair_log.csv` 에 남긴다.
- 가동 여부는 전력이 아니라 **그날 생산량 합계 == 0**(하루 단위)으로 판정한다(증강 과정에서 전력만 평일 수준으로 덮어쓴 날이 있다).

## 수정본의 결측 처리와 평가 대상

전력·풍속·공장인원 결측은 관측 원점 이후 값으로 메우지 않도록 과거값 전파(`ffill`)를 사용하고 강수량은 0으로 채운다. 학습 전처리와 서빙 이력 처리가 같은 규칙을 따르도록 유지한다. 실제 운영에서는 대상일 생산·휴무계획과 기상예보를 사전에 확보해야 한다.

피크 평가 시간은 `y_peak ≥ 187kW`로 정한다(테스트 28시간). 평균전력 `y_avg ≥ 187kW`인 2시간은 별도 고부하 평가다. 피크의 정의와 평균전력 예측의 평가 대상을 혼동하지 않는다.
