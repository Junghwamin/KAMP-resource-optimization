이 폴더는 서빙이 예측 대상일의 공휴일 여부를 판단할 때 읽는 운영 공휴일표 `holidays_kr.json` 이 있는 곳이다.

# serving/config — 운영 공휴일표

**결론**: 지금은 **2021년만** 서비스한다. 다른 해의 날짜를 예측하려면 그 해의 공휴일을 공식 출처로 확인해 이 파일에 넣어야 한다.

## holidays_kr.json

```json
{"_note": "…", "coverage_years": [2021], "dates": ["2021-01-01", "2021-02-11", …, "2021-12-25"]}
```

| 키 | 뜻 |
|---|---|
| `coverage_years` | 서비스하는 연도 목록. 지금은 `[2021]` |
| `dates` | 공휴일·대체공휴일 날짜(`YYYY-MM-DD`). 2021년 18일 |
| `_note` | 관리 안내 문장 |

- 학습 코드의 공휴일 목록은 2021-08-16 까지만 있다. 이 파일이 그 뒤(추석 9/20~22, 10월 대체공휴일, 성탄절)를 보충한다.
- **커버리지 밖의 대상일은 거부한다**: CLI 는 종료코드 2, REST API 는 HTTP **422** `CALENDAR_NOT_COVERED`.
  공휴일을 모르는 채 조용히 평일로 예측하는 것보다 안전하기 때문이다.
- 파일 형식이 틀리거나 날짜가 잘못되면 서빙이 기동하지 않는다(`HOLIDAYS_INVALID`).
- 다른 공휴일표를 쓰려면 CLI `--holidays 파일.json` 또는 환경변수 `KAMP_HOLIDAYS_FILE`.

## 새 연도를 추가할 때

1. 관보·공휴일 법령 등 **공식 출처로 확인한** 공휴일·대체공휴일·임시공휴일을 `dates` 에 넣는다.
2. 그 연도를 `coverage_years` 에 넣는다.
3. `python -X utf8 -m serving verify --bundle outputs/models/full/deploy` 로 기동이 되는지 확인한다.

주의: 모델은 2021-01~09 데이터로만 학습했다. 연도를 추가해도 10~12월과 다른 해의 예측은 **외삽**이다(`serving/README.md` 8절).

## 생산·휴무계획과의 구분

이 공휴일표는 달력 정보를 제공하며 공장의 실제 가동·휴무계획을 대체하지 않는다. `plan.csv`의 생산계획과 이력은 별도로 검증한다. 장기 휴무 관련 과대예측을 줄였다는 주장은 새 데이터와 실행 결과로 확인해야 한다.

전처리·모델 수정 후에는 `python run_all.py`로 번들을 다시 만들고 `python -X utf8 -m serving verify --bundle outputs/models/full/deploy`로 확인한다. 공휴일표 변경만으로 학습·평가가 다시 실행되지는 않는다.
