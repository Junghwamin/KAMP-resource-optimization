이 폴더는 실험 코드 11개(`s00` ~ `s10`, 장 하나에 파일 하나)가 있는 곳이며, `run_all.py` 가 이 파일들을 읽어 순서대로 실행한다.

# src — 실험 코드

**결론**: 여기 코드는 직접 실행하거나 import 하지 않는다. 항상 패키지 폴더에서 `python run_all.py` 로 돌린다.
현재 파일은 보고서 검토를 반영한 수정본이다. 기존 보고서의 숫자를 그대로 재현하는 버전이 아니므로 수정 후 FULL 실행 결과와 로그를 근거로 보고서를 갱신한다.

`show_results.py` 가 그 기록으로 보고서 순서의 쪽을 만든다. 전체 대응표는 루트 `README.md` 4절.

## 2. ⚠️ import 하면 그 장이 실행된다

이 파일들은 함수 모음이 아니라 **위에서 아래로 실행되는 스크립트**다. 파일 맨 위 코드가 곧 실험이다.
그래서 파이썬에서 `import s05_models` 를 하면 앞 장(0~4장)까지 끌어와 **그 자리에서 전부 계산하고 `outputs/` 를 덮어쓴다.**
대화형 파이썬에서 이 폴더의 모듈을 import 하지 않는다. 결과를 보고 싶으면 `python show_results.py` 를 쓴다.

## 3. 셀 표기와 실행 방식

파일은 jupytext 'percent' 형식이다. 노트북의 셀 경계를 주석으로 적어 둔 것이다.

| 표기 | 뜻 | run_all.py 의 처리 |
|---|---|---|
| `# %%` | 코드 셀 | 실행한다 |
| `# %% [markdown]` | 설명 셀 (각 줄이 `# ` 로 시작) | 제목·보고서 대응절만 읽는다 |
| `# %% tags=["nb-strip"]` | 앞 장 모듈을 import 하는 셀 | **버린다** — 노트북을 조립할 때도 버리는 셀이다 |

`run_all.py` 는 모든 코드 셀을 **하나의 이름공간에서 차례로** 실행한다(노트북 커널과 같은 방식). 그래서 nb-strip 셀이 없어도
앞 장에서 만든 변수를 뒤 장이 그대로 쓴다. `## N.` 은 장, `### N.M 제목` 은 절(= 단계), `### N장 게이트 — …` 는 게이트 단계 `N.G` 다.
각 장 끝의 게이트 1~4 는 점검이 실패하면 멈춘다(6장 게이트는 표로만 남는다 — `outputs/tables/README.md`).

## 4. 이 패키지에서 뺀 절과 이유

보고서 문장·초안·발표자료를 만들거나 개발 저장소 전체를 검사하는 절이다. 실험 결과(모델·지표·표·그림·예측)는 바뀌지 않는다.

| 파일 | 뺀 절 | 하는 일 (뺀 이유) |
|---|---|---|
| `s06_eval.py` | 6.7 | 보고서 서술을 실측에 맞춰 교정하는 표 |
| `s08_simulation.py` | 8.5 | 보고서 4장 본문 초안 생성 |
| `s09_creativity.py` | 9.1 ~ 9.6 전부 | 차별점 정리와 보고서 5장 초안 생성 |
| `s10_package.py` | 10.2 · 10.3 · 10.4 · 10.6 · 최종 게이트 | 보고서 채움표·README·requirements 생성, 발표자료 골격·개인정보 스캔, 제출 준비 점검 (개발 저장소 파일을 전제로 한다) |

뺀 코드가 만든 이름을 남은 코드가 쓰는 경우는 없다(정적 분석으로 확인). 실행 계획은 `python run_all.py --list` 로 볼 수 있다.

## 5. 다른 폴더와의 관계

- `tools/model_persistence.py` — s04·s05 가 비교 모델을 저장할 때 쓴다(`tools/README.md`).
- `serving/_core.py` — s01·s02 의 전처리·피처 함수와 s10 의 번들 예측 함수 **원문을 자동으로 옮겨 만든 파일**이다.
  전처리·피처·번들 예측 로직을 바꾼 뒤 `python tools/build_serving_core.py`로 재생성하고 `python tools/build_serving_core.py --check`로 동기화를 확인한다. 인과성 테스트·번들 리플레이로 학습과 서빙의 동작도 검증한다. 생성 파일을 따로 편집하지 않는다.
- `run_all.py` 는 실행할 때마다 이 파일들의 sha256 을 `outputs/steps/index.json` 의 `provenance` 에 기록한다(어떤 코드로 만든 결과인지 증명).
- `tools/isolated_regime_cv.py` — 6.6의 레짐 변형별 CV를 새 프로세스로 분리하고 검증된 OOF 숫자 배열을 반환한다. 기본 작업 캐시는 `.cache/regime_cv`이며 `KAMP_WORK_DIR`로 변경할 수 있다. 소스·데이터·프레임·설정·런타임·바이너리 지문과 결과 해시·완료 상태가 일치하는 캐시만 재사용한다.

## 6. 수정본에서 확인할 경계

- `s01`·`s02`와 `serving/_core.py`: 과거값 전파를 사용하는 인과적 결측 처리. 예측 원점 이후 값을 바꿔도 해당 원점의 피처가 변하지 않아야 한다.
- `s03`·`s06`: 실제 최대전력 피크 시간의 `Peak-MAE`·`Peak15-MAE`·표본 수와 평균전력 고부하 지표를 분리한다. RF 대비 MAE 감소량의 95% 기본 구간과 90% 사후 보조 구간을 함께 저장한다.
- `s05`: HPO와 최종 학습의 `bagging_freq`·`n_estimators`를 일치시킨다. 확률 보정 성능은 시간순 교차적합으로 평가하고, 번들용 보정기는 전체 OOF로 적합한다.
- `s05`·`s06`: fold별 모델 참조 해제와 가비지 수집을 적용하고 6.6 레짐 변형은 프로세스를 분리한다. 시드·트리·스레드 설정을 바꾸지 않는다. 재실행 시 앞선 단계까지 건너뛰는 전체 이어하기 기능으로 해석하지 않는다.
- `s07`: 실패사례의 과대·과소예측 설명을 실제 오차 부호에 맞춘다.
- `s08`: 전력량요금 절감은 산정하지 않고 기본요금·인건비·순절감의 기간을 맞춘다. 부하 이동 후 관측 최대를 넘는 새 피크를 상한으로 잘라내지 않고 초과 여부·시간 수를 저장한다. 연간 기본요금 환산액은 별도 참고값이며, L1c 중심 현장시험과 조건부 L2 추가를 제안한다.

각 수정의 통과 여부와 최신 결과는 `tests/README.md`, `outputs/steps/index.json`, 생성 CSV에서 확인한다.
